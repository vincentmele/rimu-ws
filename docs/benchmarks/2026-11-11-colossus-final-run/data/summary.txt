## phase X: connection closes and errors of the rimu starts (carried checks of Tasks 21 to 23d)

The server counts no closes by code (the h3 stats line has no such counter), and `error_cb` (ARENA_LOG_ERRORS=1) reports worker-level errors only. So a close with 0x0107 (excessive load) or InternalError / PoolExhausted is read from what it does to the client: h2load counts the requests of a closed connection as failed or errored, summed per start in `errors` (which also counts non-2xx statuses), and every rimu start must have 0. Beside it the server's own totals per start (the last `h3-stats` line of its log): handler panics, UDP send errors, stateless resets (a reset answers a datagram for a connection the worker no longer has), datagrams dropped when forwarding, `frames_resent_acked` (must be 0; `prev` has no such counter) and the worker-level `arena-h2:` error lines.
